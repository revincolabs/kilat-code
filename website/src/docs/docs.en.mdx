## Quick start

1. Make sure the [requirements](#requirements) are installed: at least Git and either the Claude Code CLI or the Codex CLI.
2. [Download Kilat Code](#installation) for Windows, macOS, or Linux, install it, and open it.
3. Click **Akun & Pengaturan** (Accounts & Settings) in the bottom left. Two accounts are already there: *Claude (login bawaan)* and *ChatGPT (login bawaan)* (default login) use the CLI logins already on your computer. Add more accounts if you need them.
4. Click the folder button next to **Thread baru** (New thread) to open a project folder.
5. Click **Thread baru**. The agent's terminal starts in that folder right away. Type your task as usual.

<Note>
**Tip:** a new thread uses the account, model, and mode you used last. All of them can be changed from the bar above the terminal.
</Note>

## Requirements

| Component | Required? | Notes |
|---|---|---|
| Operating system | Yes | Windows 10/11 (64-bit), macOS 11 or later (Apple Silicon & Intel), or Linux x86_64. Windows is the most tested; macOS and Linux are still early. |
| System webview | Yes | Windows: Microsoft Edge WebView2 (built into Windows 11 and most Windows 10 installs). macOS: built in. Linux: WebKitGTK 4.1 (`libwebkit2gtk-4.1-0` on Ubuntu/Debian, `webkit2gtk4.1` on Fedora). |
| Git | Yes | For worktrees, diffs, and commits. On Windows, install Git for Windows, which also provides Git Bash. |
| Secret store | Linux only | GNOME Keyring or KWallet (Secret Service) to store tokens. Windows uses Credential Manager and macOS uses Keychain. |
| Claude Code CLI | One of the two | For Claude agents. The `claude` command must run. |
| Codex CLI | One of the two | For ChatGPT agents. The `codex` command must run. |
| GitHub CLI (`gh`) | Optional | For multiple GitHub accounts and creating pull requests. |
| Subscription or API key | Yes | Claude Pro/Max or an Anthropic API key, and/or ChatGPT or an OpenAI API key. |

Kilat finds these programs automatically. If one is missing, the status bar at the bottom shows a warning, and you can enter its location in [Settings](#settings).

## Installation

<DownloadBox lang="en" />

All files are also on the <a href={RELEASES_URL}>GitHub Releases</a> page.

### Windows

1. Run the `-setup.exe` file.
2. If you see *"Windows protected your PC"*, click **More info** and then **Run anyway**. The warning appears because the installer isn't code-signed yet.
3. Kilat installs for your Windows user only, in `%LOCALAPPDATA%\Kilat Code`, without admin rights. Open it from the Start menu.

### macOS

1. Open the `.dmg` file and drag **Kilat Code** into **Applications**.
2. The app isn't notarized by Apple yet, so the first time you open it: right-click **Kilat Code** in Applications → **Open** → **Open**. If macOS says the app is "damaged", run this in Terminal:

   ```bash
   xattr -cr "/Applications/Kilat Code.app"
   ```

3. Kilat reads the PATH from your login shell (zsh/bash), so `claude`, `codex`, and `gh` installed with Homebrew or npm are found even when Kilat is opened from the Dock.

### Linux

- **AppImage** (any distribution): make it executable, then run it.

  ```bash
  chmod +x KilatCode_*.AppImage
  ./KilatCode_*.AppImage
  ```

- **.deb** (Ubuntu, Debian, and derivatives):

  ```bash
  sudo apt install ./KilatCode_*.deb
  ```

- **.rpm** (Fedora and derivatives, from v0.2.1). `dnf` also installs the WebKitGTK it needs:

  ```bash
  sudo dnf install ./KilatCode_*.rpm
  ```

  On earlier versions, Fedora users can use the AppImage. AppImages need FUSE 2, which Fedora doesn't install by default: run `sudo dnf install fuse-libs` first.

Tokens are stored through Secret Service, so make sure GNOME Keyring or KWallet is running in your desktop session.

### Updates

Kilat checks for new versions itself (a few seconds after it opens, then every 6 hours). When one is available, a yellow **Update ke vX** (Update to vX) button appears in the status bar: click it and Kilat downloads, installs, and restarts. You can also use **Pengaturan → Periksa update** (Settings → Check for updates). Updates are signed, so only official ones are accepted. On Linux, automatic updates apply to the AppImage; with the `.deb`, install the new `.deb`. Accounts, settings, and threads are kept. Running agents stop when Kilat restarts, but their sessions continue when you open the thread again.

## Adding accounts

All accounts are managed in **Akun & Pengaturan** (Accounts & Settings, bottom left). Every account needs a **unique name** (e.g. "Claude Work"). Email and plan (Pro, Max, Plus, …) are detected automatically, so you always know which account is in use.

### Claude (Pro/Max subscription)

1. Open the **Claude** tab, enter a name, and click **+ Login langganan (Pro/Max)** (sign in with subscription).
2. Step 1: a small terminal runs `claude setup-token`. Click *Authorize* in the browser. The token is valid for one year, captured automatically, checked with Anthropic, and stored in your system's secret store.
3. Step 2: sign in once more in the browser, only to read the account's email and plan. This login is deleted right after it's read.

<Note>
**Important:** before you start, make sure the browser is signed in to the right Claude account. If the email that comes back belongs to another Claude account you already added, Kilat rejects it so accounts don't get mixed up. Older accounts whose email hasn't been detected have a **Deteksi email** (Detect email) button.
</Note>

### Claude (API key)

Enter a name, paste an `sk-ant-api…` API key, and click **Pakai API key** (Use API key). The key is checked with Anthropic before it's saved.

### ChatGPT / Codex

Open the **ChatGPT / Codex** tab, enter a name, and click **+ Login ChatGPT**. Kilat runs `codex login` in a folder that belongs to that account. You can also use an OpenAI API key.

### GitHub

Click **+ Login akun GitHub baru** (sign in to a new GitHub account), which runs `gh auth login`, or **Impor dari gh** (Import from gh) if you've already signed in with `gh`. The commit name and email and an SSH key can be set per account.

## Projects and threads

A **project** is a folder on your computer. A **thread** is one conversation with an agent in that project, shown as a terminal.

- **Thread baru** (New thread) creates a thread in the active project. The **+** button next to a project name does the same.
- **Thread di worktree terpisah** (Thread in a separate worktree, in the project's **⋯** menu): Kilat creates a git worktree and a `kilat/…` branch just for that thread, so several agents can change files without overwriting each other.
- The thread title is filled in from your first message. Double-click the title in the top bar to rename it.
- Hover a thread to pin, archive, or delete it. The search box filters by title.
- The dot next to a thread shows its status: blinking yellow = working, green = ready, orange = needs permission or hit a limit (limited threads also get a clock icon), grey = the agent isn't running. The letters **C** / **G** mark Claude or ChatGPT.

Deleting a thread stops its agent. The original Claude/Codex session stays in `~/.claude` / `~/.codex`.

## The agent terminal

A thread is the real `claude` or `codex` terminal. Anything you can do in a normal terminal works here: slash commands, `/model`, approving permissions, bash mode, and so on.

- **Agents keep running in the background.** Switching to another thread doesn't stop them. When you come back, the screen is redrawn.
- The circular arrow on the right of the bar above the terminal restarts the agent and continues the same session. The square button next to it stops the agent.
- If the agent stops (for example, you type `/exit`), a **Jalankan lagi** (Run again) button appears and continues the previous session.
- Claude's status line at the bottom of the terminal shows `⚡ Kilat · account name · plan · usage`, so you always know which account you're using.

### Keyboard in the terminal

| Keys | Action |
|---|---|
| <kbd>Enter</kbd> | Send the message to the agent. |
| <kbd>Shift</kbd>+<kbd>Enter</kbd> | New line in the agent's input. |
| <kbd>Ctrl</kbd>+<kbd>V</kbd> | Paste. |
| <kbd>Ctrl</kbd>+<kbd>C</kbd> | Copy if text is selected. Otherwise it's sent to the agent (interrupting what's running). |
| <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd> | Always copy. |

On macOS, copy and paste use <kbd>⌘</kbd>+<kbd>C</kbd> / <kbd>⌘</kbd>+<kbd>V</kbd>, and <kbd>Ctrl</kbd>+<kbd>C</kbd> always goes to the agent.

## Models and permission modes

The bar above the terminal has a **model** and a **permission mode** picker. Changing either restarts the agent in the same session with the new setting. You can also change the model with `/model` in the terminal.

| Mode | Claude Code | Codex |
|---|---|---|
| Akses penuh (Full access) | `--dangerously-skip-permissions` | `--dangerously-bypass-approvals-and-sandbox` |
| Setelan CLI (CLI settings) | no flag, follows the CLI's settings (e.g. auto mode) | no flag, follows `config.toml` |
| Minta izin (Ask for permission) | `--permission-mode default` | `-s workspace-write -a on-request` |
| Plan / read-only | `--permission-mode plan` | `-s read-only -a on-request` |

<Note warn>
**Full access** means the agent can run commands and change files without asking. The first time, Claude Code shows a *Bypass Permissions* warning that you have to accept yourself in the terminal. Only use this mode in projects you trust.
</Note>

## Switching accounts and providers

The account dropdown above the terminal lists all Claude and ChatGPT accounts. Pick another account and the agent restarts with it. If the agent is in the middle of something, Kilat asks first.

| Switch | How the context is kept |
|---|---|
| Claude → Claude | All Claude accounts share the same session storage. The agent continues with `--resume` in the same session; only the account token differs. |
| ChatGPT → ChatGPT | Each account has its own login folder, but the session folder is shared. `codex resume` continues the same thread. |
| Claude ↔ ChatGPT | Kilat writes the part of the conversation the target agent hasn't seen (your messages, the agent's replies, and the commands and files it touched) to a Markdown file, then asks the target agent to read it before continuing. |

Kilat records the account and the original session for every part of the conversation. When you go back to a provider you used before, its session continues and only what happened since is handed over.

## When you hit a limit

Kilat detects limits automatically: from Claude Code's `StopFailure` hook, or from Codex's session files. The thread gets an orange clock icon, you get a notification, and a dialog with three options appears above the terminal.

### 1. Wait

Kilat shows the reset time, read from the CLI's usage data or from the limit message (e.g. *"resets 3pm"*, *"try again at …"*). Choose **Tunggu sampai …** (Wait until …) or another duration (30 minutes, 1, 3, or 5 hours). When the time comes, Kilat restarts the agent in the same session and sends a follow-up message. This works while Kilat is open; if Kilat is closed, the work continues as soon as you open it again. While waiting, an orange bar above the terminal has **Lanjut sekarang** (Continue now) and **Batal** (Cancel) buttons.

### 2. Move to another Claude account

A list of your other Claude accounts with their usage. Click one: the same session continues on that account, and the agent is asked to pick up where it stopped.

### 3. Move to a ChatGPT account

Click a ChatGPT account: Codex starts with the conversation history as context and is asked to continue the last task.

<Note>
The follow-up message can be changed in [Settings](#settings) (default: *"Lanjutkan pekerjaan yang tadi terhenti karena limit akun."*, "continue the work that stopped because of the account limit"). The × button closes the dialog if you'd rather handle it yourself.
</Note>

## Account usage

- **Claude:** the 5-hour and 7-day window percentages, reported by Claude Code through the status line.
- **Codex:** the limit windows from Codex's session files.

Usage appears in the account dropdown, the limit dialog, and the account list in Settings, with reset times. Accounts that are currently limited get a clock icon. If a limit has already passed, click **Hapus tanda limit** (Clear limit mark) in the account list.

<Note>
If you set your own `statusLine` in `~/.claude/settings.json`, Kilat doesn't overwrite it. Claude usage then isn't read, but limits are still detected.
</Note>

## Skills, plugins, and MCP

Because Kilat runs the official CLIs with your own configuration, everything you've installed keeps working:

- **Claude Code:** all Claude accounts use the same `~/.claude` folder. Plugins, skills, MCP servers, hooks, `CLAUDE.md`, and settings apply to every account. Kilat's own hooks are added, not substituted for yours.
- **Codex:** the `skills`, `rules`, `prompts`, `plugins`, and `sessions` folders are linked to `~/.codex`, while `config.toml` (including MCP servers) and `AGENTS.md` are copied into every ChatGPT account before the agent starts.

Install skills or plugins as usual from any agent terminal. They're available on the other accounts right away.

## Editor, diff, and commit

The buttons in the top right open a side panel:

- **Editor:** a file explorer and editor (CodeMirror) for quick looks and edits. <kbd>Ctrl</kbd>+<kbd>P</kbd> finds a file.
- **Perubahan** (Changes): git status, a diff per file, and checkboxes for the files to commit.
  - **Buat pesan** (Write message): the agent writes a commit message from the diff, using the active thread's account.
  - **Commit**, **Commit & Push**, **Push**, **+ branch**.
  - **Buat PR** (Create PR): push, then create a pull request with `gh`, optionally as a draft.

## Multiple GitHub accounts

Pick a GitHub account per project in the **status bar** at the bottom. The choice applies right away to the bash terminal, the agents, and the Changes panel, including ones that are already running, without a restart.

How it works: every process in that project uses its own `GIT_CONFIG_GLOBAL`, which *includes* your `~/.gitconfig`, then overrides the commit name and email and adds a credential helper that gets the selected account's token from `gh`. Switching accounts only rewrites two small files.

## Bash terminal

Besides the agent terminals, there's a terminal panel at the bottom: Git Bash on Windows, your default shell (zsh/bash) on macOS and Linux. Open or close it with <kbd>Ctrl</kbd>+<kbd>{"`"}</kbd> (<kbd>⌘</kbd>+<kbd>{"`"}</kbd> on macOS) or the **Terminal** button. It can have several tabs, and it uses the project's GitHub account too.

## Notifications

When the Kilat window isn't focused, you get a system notification (and a sound, if enabled) when an agent **finishes**, **needs permission**, or **hits a limit**. If Kilat is focused but you're in another thread, a small toast appears.

## Data and privacy

- Kilat **has no servers**. There's no Kilat account and no telemetry.
- Claude tokens and API keys are stored in your **system's secret store**, not in plain files: Credential Manager (Windows), Keychain (macOS), or Secret Service such as GNOME Keyring / KWallet (Linux).
- App data (projects, the account list without secrets, threads, settings) is in `%APPDATA%\dev.kilat.code` (Windows), `~/Library/Application Support/dev.kilat.code` (macOS), or `~/.local/share/dev.kilat.code` (Linux).
- Conversations are stored by each CLI in `~/.claude` and `~/.codex`, exactly as without Kilat. Claude ↔ ChatGPT handoff files are in the `handoff` folder of Kilat's data.
- Kilat itself only contacts Anthropic to check the Claude tokens you save (whether they're valid and whose they are), and GitHub through `gh` for account profiles. All other traffic comes from the official CLIs.

## How it works

- Each thread runs `claude` or `codex` in a pseudo-terminal (ConPTY on Windows, a PTY on macOS/Linux), displayed with xterm.js. The process belongs to the app, not to the view, so it keeps running when you switch threads.
- **Claude:** Kilat adds a settings file through `--settings` with `SessionStart`, `UserPromptSubmit`, `Stop`, `StopFailure`, and `Notification` hooks and a status line. The hooks call `kilat.exe --kilat-hook`, a tiny process that forwards the data to Kilat over a local `127.0.0.1` socket with a random key, then exits.
- **Codex:** Kilat reads the session (rollout) files Codex writes to learn the session id, working state, usage, and limits. Codex runs with `--no-daemon` so each account really uses its own login.
- **Accounts:** Claude accounts are told apart through `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY`; ChatGPT accounts through their own `CODEX_HOME`.

## Troubleshooting

### "tidak ditemukan: claude / codex / bash / gh" (not found) in the status bar

Install the program, or enter its location in [Settings](#settings) under *Lokasi program* (Program locations). For Claude Code, try running `claude --version` in a normal terminal first.

### A thread says "belum di-setup" (not set up) or "belum login" (not signed in)

Open Akun & Pengaturan (Accounts & Settings) and finish the setup for that account, or pick another account from the dropdown above the terminal.

### Claude asks about trusting the folder or shows the Bypass Permissions warning

Those are Claude Code's own one-time dialogs. Answer them in the terminal. If you don't want the Bypass Permissions warning, use the *Setelan CLI* (CLI settings) or *Minta izin* (Ask for permission) mode.

### The reset time is unknown

Pick one of the wait durations (30 minutes to 5 hours). You can press **Lanjut sekarang** (Continue now) at any time.

### Claude usage doesn't show

The numbers appear after the agent sends its first request. If you have your own `statusLine`, see the note under [Account usage](#account-usage). API key accounts don't have 5-hour/7-day windows.

### The terminal looks garbled after switching threads

Resize the window slightly, or click the restart button (circular arrow) in the bar above the terminal. The agent redraws its screen.

## Uninstalling Kilat

- **Windows:** Settings → Apps → Installed apps → *Kilat Code* → **Uninstall**.
- **macOS:** drag *Kilat Code* from Applications to the Trash.
- **Linux:** delete the AppImage, run `sudo apt remove kilat-code` for the `.deb`, or `sudo dnf remove kilat-code` for the `.rpm`.

Kilat's data folder (see [Data and privacy](#data-and-privacy)) and the tokens in your system's secret store (entries containing `kilat-code`) can be removed by hand for a full cleanup. Sessions in `~/.claude` and `~/.codex` are left untouched.
